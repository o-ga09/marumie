# バックエンドAPI概要

## 目的

現在のNext.jsモノリシック構成から、バックエンドロジックを独立したAPIサーバーに切り出し、フロントエンドとバックエンドを疎結合にします。

## アーキテクチャ

### 現状
```
┌─────────────────────────────────────┐
│         Next.js (webapp)            │
│  ┌──────────────┬────────────────┐  │
│  │  Frontend    │   Backend      │  │
│  │  (React)     │   (Server)     │  │
│  │              │   ↓            │  │
│  │              │   Prisma       │  │
│  └──────────────┴────────────────┘  │
└─────────────────────────────────────┘
                 ↓
        ┌───────────────┐
        │   PostgreSQL  │
```

## 技術スタック

### バックエンドAPI候補
- **Express.js** + TypeScript（軽量、実績豊富）
- **Fastify**（高速、TypeScript対応が良好）
- **NestJS**（エンタープライズグレード、DIコンテナ）
- **tRPC**（型安全なRPC、フルスタックTypeScriptに最適）

### 推奨: Fastify + tRPC
- Fastifyで高速なAPIサーバーを構築
- tRPCでフロントエンドとバックエンドの型安全性を確保
- Prismaをそのまま活用
- Zodによるバリデーション

## API設計原則

### RESTful API設計
- リソース指向のURL設計
- 適切なHTTPメソッド（GET, POST, PUT, DELETE）の使用
- ステータスコードの適切な使用（200, 201, 400, 404, 500など）

### 認証・認可
- Supabase Authを利用したJWT認証
- 管理画面用APIは認証必須
- 公開データは認証不要

### エラーハンドリング
- 統一されたエラーレスポンス形式
- 適切なエラーメッセージとステータスコード

### パフォーマンス
- ページネーション必須
- キャッシュ戦略（Redis検討）
- データベースクエリの最適化

## 主要機能カテゴリ

### 1. 政治団体管理 (Political Organizations)
- 政治団体の一覧取得、詳細取得
- 政治団体の作成、更新、削除（管理画面用）

### 2. トランザクション管理 (Transactions)
- トランザクションの一覧取得（フィルタリング、ページネーション）
- トランザクションの詳細取得
- CSVアップロードによる一括登録（管理画面用）
- トランザクションの削除（管理画面用）

### 3. データ集計・可視化 (Analytics)
- 月次収支集計
- サンキー図データ集計（政治資金規正法カテゴリ、フレンドリーカテゴリ）
- 貸借対照表データ
- 寄付金推移データ
- CSVエクスポート

### 4. 残高スナップショット (Balance Snapshots)
- 残高スナップショットの一覧取得
- 残高スナップショットの作成、削除（管理画面用）

### 5. 認証・認可 (Authentication)
- ユーザー認証（Supabase Auth）
- アクセス制御（管理者/一般ユーザー）

## マイグレーション戦略

### フェーズ1: API構築
1. バックエンドAPIプロジェクトの新規作成
2. Prismaスキーマの共有化
3. 既存Usecaseの移植
4. APIエンドポイントの実装

### フェーズ2: フロントエンド統合
1. APIクライアントの作成（tRPC client / fetch wrapper）
2. webappのServer Actionsを段階的にAPI呼び出しに置き換え
3. adminのServer Actionsを段階的にAPI呼び出しに置き換え

### フェーズ3: 最適化
1. キャッシュ戦略の実装
2. パフォーマンス最適化
3. モニタリング・ロギング強化
4. CI/CDパイプラインの整備

## 開発環境

### 必要なツール
- Node.js 20+
- pnpm
- Docker（PostgreSQL用）
- Supabase CLI

### ローカル開発
```bash
# バックエンドAPI起動
pnpm run dev:api

# フロントエンド起動
pnpm run dev:webapp
pnpm run dev:admin
```

## セキュリティ考慮事項

### 環境変数
- データベースURL
- Supabase Auth設定
- API秘密鍵
- CORS設定

### データ保護
- 個人情報の適切な取り扱い
- SQLインジェクション対策（Prismaで自動対応）
- XSS対策
- CSRF対策

### レート制限
- API呼び出し回数の制限
- DDoS対策

## パフォーマンス目標

- API応答時間: 95パーセンタイルで200ms以内
- データベースクエリ: 平均50ms以内
- 同時接続数: 1000以上
- スループット: 10,000リクエスト/分以上
